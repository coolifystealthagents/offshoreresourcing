## Research question

Published September 2, 2026. Backlog recovery fails when teams add output targets without reducing inflow, protecting review capacity, or deciding which commitments can move.

## Findings

A useful model separates items by age, consequence, complexity, and decision dependency, then estimates safe daily completion and acceptance rates.

Recovery should have an exit threshold and a named owner so temporary shortcuts do not become the new operating standard.

## Practical takeaways

- Measure net backlog movement rather than completions alone.
- Prioritise by consequence and age with an authorised owner.
- End temporary controls only after quality and queue age recover.

## Control table

| Signal | Evidence | Accountable response |
| --- | --- | --- |
| Backlog by risk tier | Queue export | Service owner sets sequence |
| Daily inflow | Intake records | Queue owner controls new work |
| Accepted recovery output | Review records | Manager protects review capacity |
| Exit threshold reached | Age and defect trend | Service owner closes recovery mode |

## Implementation routine

Start with one current workflow and a short review period. Record the baseline, apply one agreed control, and compare the same measures at the next checkpoint. Contributors can assemble evidence and flag exceptions; managers retain decisions about access, staffing, policy, budget, employment, and customer commitments.

## Key stats

- Four defect classes cover the main pre-publication QA surface: factual, structural, accessibility, and metadata.
- WCAG 2.2 organizes accessibility requirements under four principles: perceivable, operable, understandable, and robust.
- Any unsupported headline claim is a release-blocking defect.

## Key takeaways

- Severity should determine owner and response time.
- Fix source and schema defects before style preferences.
- Re-run checks after every material correction.

## Severity matrix

| Severity | Example | Action |
| --- | --- | --- |
| Blocker | Unsupported statistic or broken canonical | Do not publish |
| High | Missing source note or misleading table | Reviewer correction |
| Medium | Weak internal link or unclear label | Queue for revision |
| Low | Minor style inconsistency | Batch cleanup |

## Operating method

Use the [offshore content QA checklist](/research/offshore-content-qa-checklist) for the first pass and [content accessibility review](/research/content-accessibility-review) for the interface pass. Keep the defect record with the article so recurring errors can become a training control.

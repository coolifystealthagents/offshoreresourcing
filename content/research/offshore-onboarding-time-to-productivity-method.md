## The question and its boundary

Onboarding is usually described as a schedule: week one for tools, week two for shadowing, week three for live work. The schedule does not show whether the person can actually complete the work. This note proposes a narrower measure: the time from start date to the first independently completed item that passes review without correction.

The measure is local and descriptive. It does not rate the individual, compare providers, or predict tenure.

## Define the standard task

Choose one or two tasks that are central to the role and stable during the observation period. A task with a written acceptance standard and a reviewable output works; a vague "help the team" does not.

Record the task, the source input, the expected output, the reviewer, and the pass rule. Freeze the version used for the cohort so later changes do not distort the result.

## Set the observation rules

Start the clock on the first working day. Stop it on the date the reviewer records a pass with no correction. A pass with minor formatting notes can count only if the rule says so before the cohort starts.

Record each attempt, the correction reason, and the reviewer. Keep coaching notes separate from the pass record.

## Handle common distortions

A new hire who joins during a quiet period may pass quickly because the tasks are easy. Record volume and task mix beside the result. A cohort that starts before a process change is not comparable with one that starts after.

Exclude time waiting for access only if the wait is separately recorded. Otherwise the measure hides a real onboarding dependency.

## Report and use the result

Report the cohort size, the median, the range, and the share still not passed at the review date. A single number invites false precision.

Use the result to find the slowest step: access, tool training, example quality, or review availability. Fix the step before setting a faster target.

## Limitations

The method measures one task, not overall capability. It depends on reviewer consistency and can be gamed by choosing easy work.

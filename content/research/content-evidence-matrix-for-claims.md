## Key stats

- A six-column matrix connects claim, source, date, limitation, reviewer, and wording.
- Every headline number should have one visible evidence path.
- A limitation note prevents precision from being mistaken for certainty.

## Key takeaways

- Separate evidence from editorial interpretation.
- Record limitations next to the number they qualify.
- Reconcile the matrix after human editing, not only before drafting.

## Matrix fields

| Field | Purpose | Example |
| --- | --- | --- |
| Claim | Defines the assertion | Employment grew 4% |
| Source | Supports retrieval | BLS table |
| Limitation | Prevents overclaiming | Projection, not result |
| Wording | Controls final expression | “projected to grow” |

## Operating method

Begin with the [content fact-checking evidence matrix](/research/content-fact-checking-evidence-matrix), then use the [source verification workflow](/research/source-verification-workflow) for disputed rows. Claims that cannot be mapped should be removed, softened, or researched again before release.

Equipment issued to an offshore worker can outlive the role if the return is not recorded. A laptop, a headset, a security token, or a mobile device may be shipped back, handed to a local lead, or kept by the worker with an informal promise to return it later. The risk is not only the replacement cost; an unreturned device can still hold access, data, and a recognizable company identity. This protocol defines a completeness check for the return record at the end of a role. Review [offshore staffing services](/services) and the [research library](/research) before you apply it to a live exit.

The method treats the return record as evidence, not as a checklist that someone signs at the door. A record is complete when it shows what was issued, what came back, who received it, when, and what happened to any item that did not return. A missing item should be visible as an exception with an owner, not hidden in a closing email. The reviewer should be able to answer what happened to the item without opening a separate chat thread.

## Research question and decision supported

The question is how many issued items have a complete return record at the end of an offshore role, and which items or steps account for the gaps. The decision supported is whether the exit process is reliable enough to close the role, and which control needs repair. A second decision is whether an unreconciled item requires a security action such as a remote wipe or an access review. The report should also name the person who approved the exit and the date the role was closed.

Write the answer as a completeness rate by item type and a list of exceptions. Do not report only the overall rate, because a high rate for headsets can hide a low rate for laptops or tokens. The item type is where the risk and the fix usually differ. If an item type has a very small count, report the raw number as well as the rate so the reader can judge the evidence.

## Scope and definitions

Define equipment as any tangible item issued for the role, including a laptop, monitor, headset, phone, token, card, bag, or cable kit. Include items purchased by the company and items reimbursed to the worker. Exclude software licenses and accounts, which belong in the access removal record even when they are bundled with a device. If a worker bought an item and was reimbursed, the receipt belongs in the same register as a company purchase.

Define a complete return record as one that links the issued item to a return event, a receiving person, a date, and a condition note. If the item was not returned, the record is complete only when it names the reason, the owner of the follow-up, and the security action taken. A record that says closed without those fields is incomplete. If the item was transferred to another worker, the record should name the new holder and the date of the transfer.

## Required fields

The register should include the item identifier, the type, the serial number or asset tag, the issue date, the assigned person, the role, the expected return date, the actual return date, the receiving person, the condition, and the disposition. Add a field for the shipping carrier and tracking number when the item travels. Add a field for the evidence link, such as a photo or a signed receipt. A missing serial number should be treated as a gap, because the identifier is what links the register to the return evidence.

The exit record should include the person, the last working day, the manager, the item list, the return status for each item, and the access removal confirmation. Link the two records by the person and the item identifier. A return record that cannot be joined to the access record leaves the reviewer guessing whether the device still has a live session. If the access record is closed before the equipment record, the reviewer should check that the device was wiped before the account was disabled.

## Population and sampling

The population is the set of roles that ended during the review period and the equipment issued to each role. Include voluntary exits, contract endings, and transfers, because the return risk is not limited to one exit type. Exclude roles that never received equipment, but count them so the denominator is clear. If a role ended without equipment, record the confirmation so the denominator includes the clean exits.

Sample all exits in a small program, or a random sample stratified by role and location in a larger one. Include at least one exit with a disputed item and one with a remote return. Review the record from issue to closure rather than only the final signature. The path often shows where the evidence was lost.

## Verification method

Verify each record against three sources: the asset register, the return receipt or shipping record, and the access removal record. Check that the item identifier matches, that the dates are plausible, and that the receiving person is authorized. For a device that was not returned, check that the remote wipe or account disable was completed and recorded. If the carrier record is unavailable, use the receiving person signed note and mark the evidence as weaker.

Ask the manager to confirm the return for a sample of items, especially when the receipt is a chat message or an informal note. A confirmation from the manager is weaker than a carrier record but stronger than an unsigned checklist. Record the source for each confirmation so the reviewer can weigh it. If the manager cannot confirm the return, record the item as unresolved rather than closing it on a verbal promise.

## Common gaps

Common gaps include an item issued informally and never added to the register, a return recorded without an item identifier, a shipping label created but not tracked, and a device kept by a local lead without a transfer record. Another gap is a return recorded after the access was removed, which can leave the device offline but still holding data. The review should look for these patterns. A pattern of informal issue is a process gap, and the fix belongs at the point where equipment is handed out.

A gap is not always a loss. A headset may be retained under a local policy, or a monitor may be transferred to a replacement hire. The record is complete when the policy and the transfer are documented. The problem is the undocumented retention, not the retention itself. Ask the exiting worker to confirm the policy that applies.

## Security and access linkage

The return record should confirm that the device was wiped, that the account was disabled, and that any token or certificate was revoked. A physical return without a wipe can leave data on the disk, while a wipe without a return can leave the company without an asset. Both checks belong in the same closure decision. If the device is in transit, record the carrier, the tracking number, and the date the wipe will be confirmed.

Set a time limit for the security action after the last working day. If the device is in transit, record the expected arrival and the interim control. Do not mark the role closed while a device with live credentials is unaccounted for. The reviewer should be able to see the status without opening a separate ticket.

## Privacy and handling

Use asset identifiers and role labels in the working file. Keep the person's home address and personal contact details out of the review unless they are needed for the return. If a shipping record includes a home address, store it in the approved system and reference it rather than copying it into the report. If the shipping record contains a home address, reference the record instead of copying the address into the review.

Apply the same retention rule to the return evidence as to other exit records. Delete working copies when the review is complete. If the device contains customer data, follow the incident process for any loss or delayed wipe. The review should not create a second store of sensitive information. Name the person who confirms the deletion.

## Limitations and error

The review may miss an item that was never registered, because the sample can only check what the records know about. It may also treat a local transfer as a loss if the transfer record is informal. State both limits and describe how the sample was chosen. State the sample method and the review period so a reader can see how much of the exit population was covered.

The manager may confirm a return from memory, which is weaker than a receipt. Mark the evidence source for each item and avoid presenting a memory-based confirmation as a verified return. If the sample is small, describe the result as a signal rather than a complete audit. If the sample is small, report the exceptions by name and avoid a percentage that suggests more precision than the data supports.

## Reporting and decisions

Report the number of roles, the number of items, the completeness rate by item type, and the exceptions with owners. Include a short list of fixes such as a mandatory asset tag at issue, a carrier tracking field, or a link between the return record and the access record. Give each fix a date. Add the date of the next review so the report has a follow-up point rather than ending with a list.

Decide whether the exit process is ready, needs a repair, or needs a manual review for a specific role. Repeat the check after the fix and compare the exception count. A complete return record protects the asset, the data, and the next person who has to close a role. If the exception count does not fall, check whether the register or the handoff changed rather than repeating the same reminder.
